# Architecture Decision Records

ADRs record durable decisions whose rationale would otherwise be rediscovered.
They complement, rather than replace, cycle notes.

Use the next four-digit number and copy `0000-template.md`. Keep superseded
records; change their status and link to the replacement.

An ADR is appropriate when a change affects crate boundaries, persistent
schemas, deterministic behavior, supported platforms, core dependencies, or a
difficult-to-reverse project policy.
